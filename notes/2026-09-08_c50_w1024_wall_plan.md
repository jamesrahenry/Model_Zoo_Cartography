# C₅₀(width=1024) wall measurement — plan (not yet run)

*Written: 2026-09-08 17:02 UTC*

Prep for candidate #2 from the post-sweep planning discussion (2026-09-06/08):
FINDINGS.md F6 flags that the Phase-2 MVP's C=40/50 partial outcomes are only
a *qualitative* replication of the expressivity wall at width=1024/depth=16 —
not a real addition to the log-frontier table, because the MVP used 8
seeds/config (vs. the table's 16–32) and no per-width lr tuning (which
mattered a lot at w=512 — see below). This note designs the real
measurement; **nothing here has been run.**

## What the existing table says

| w | C₅₀ (20k steps, tuned lr) |
|---|---|
| 64 | 27.8 [27.2, 28.5] |
| 128 | 32.3 [31.2, 33.4] |
| 256 | 36.2 [35.2, 37.3] |
| 512 | 38.8 [37.5, 39.3] |

Increments per doubling: +4.5, +3.9, +2.6 — decelerating, not constant
(the "+3.7 average" FINDINGS.md quotes is a summary, not the actual shape).
Two extrapolations for w=1024:
- **Naive average-slope (+3.7):** C₅₀(1024) ≈ **42.5**
- **Continued deceleration** (increment shrinking ~0.85-0.7× per doubling,
  so ~+1.5–2.5 next): C₅₀(1024) ≈ **40–41**

**Pre-registered prediction (before running anything): C₅₀(1024) ∈ [40, 43].**
Recorded now so the result can't be rationalized after the fact, per this
project's own discipline (F6 already has one falsification on record at
w=64 — the two-width "law" that didn't survive a third point).

## Why lr tuning is not optional to consider

At w=512, the fixed-lr (3e-4) crossing looked like a hard wall (C=64 total
stall, 0.05 acc) that was **largely an optimization artifact**: at lr=1e-4
the same config went to 16/16 partial at 0.43. The Phase-2 MVP (this
architecture, 8 seeds, fixed lr=3e-4) hasn't been checked for the same
failure mode. Historically (see F6's own dated entries) the lr-tuning need
was *discovered*, not assumed, by first running at default lr and noticing
an anomaly (e.g. unexpectedly low or bimodal convergence well below the
predicted crossing). Plan: **run default lr first, gate a tuned rerun on
the result**, rather than doubling cost upfront on an unconfirmed need.

## Proposed grid

- **C ∈ {35, 40, 45, 50, 55}** — brackets the pre-registered [40, 43] range
  with a safely-converged anchor (35) and a safely-collapsed anchor (55),
  plus three points near the expected crossing (denser than the historical
  "two informative points" pattern, given how much our two extrapolations
  disagree).
- **16 seeds/config** (not 8) — matches the table's convention, needed for
  a real binomial CI on convergence fraction.
- **wd=0** — matches the base C-sweep's convention (F6's table; wd is a
  separate axis, not the wall measurement), and keeps this comparable to
  the wd=0 arm's exact-law data once both exist.
- **lr=3e-4 first** (default, matching MVP). Gate condition for a tuned
  rerun: if convergence fraction at any config looks anomalously low/bimodal
  relative to the pre-registered crossing, or if C=55 doesn't read cleanly
  collapsed, rerun the affected configs at lr=1e-4 (matching the w=512
  precedent) before trusting the fit.

## Cost

5 configs × 16 seeds × ~16 min/net (measured rate at this architecture) ≈
**21.3 GPU-hours** for the lr=3e-4 pass alone. A gated lr=1e-4 rerun (if
triggered) would add roughly the same again for however many configs need
it — plan for a possible third night, not a certainty.
